## Дополнительная функция: внутренние участки (`/ps plot`)

### Зачем это нужно

ProtectionStones защищает территорию через установку специального блока. Эта функция позволяет **разбить уже защищённую территорию на именованные участки** без установки дополнительных блоков — просто выделяешь зону топориком WorldEdit и создаёшь участок.

Типичный сценарий — клановая территория: один игрок ставит блок и защищает большую зону, а затем раздаёт членам клана отдельные личные участки внутри неё. Каждый работает только на своём участке, не имея доступа к остальной территории.

---

## Команды

Все команды работают из любой точки мира. Аргументы с именем участка поддерживают автодополнение по Tab.

### `/ps plot create [название]`

Создаёт участок из текущего выделения деревянным топориком WorldEdit.

**Порядок действий:**
1. Выдели зону деревянным топориком (ЛКМ — первый угол, ПКМ — второй)
2. Убедись, что выделение целиком внутри твоей защищённой зоны
3. Введи `/ps plot create [название]`

> **Важно про высоту.** Участок сохраняет **точный диапазон Y выделения**, а не тянется от бедрока до неба, как приват от блока. Если щёлкнуть топориком по двум блокам на земле, участок получится высотой в один-два блока: всё, что стоит **на** земле — сундуки на поверхности, животные, сами игроки — окажется выше границы, и защита там действовать не будет.
>
> Чтобы захватить и пространство над землёй, задай углы координатами:
> ```
> //pos1 100,118,60
> //pos2 110,140,70
> ```
> Здесь `118` — нижняя граница, `140` — верхняя. Проверить получившиеся границы можно через `/ps plot list`.

**Ограничения при создании:**
- Выделение должно целиком умещаться в одной твоей защищённой зоне
- Выделение не должно перекрываться с существующим участком или чужим WG/PS-регионом, права которого новый участок смог бы перехватить
- Для U-образных и объединённых зон проверяется вся площадь выделения, а не только углы
- Имя не может совпадать с ID существующего региона
- Если цена больше нуля, нужен работающий провайдер экономики Vault; при ошибке оплаты участок не создаётся
- Участок получает приоритет родительской зоны + 10. Если у зоны приоритет настолько высок, что прибавка не поместится в целое число, создание отклоняется — приоритет не «переворачивается» в отрицательный

Команды `/ps plot` доступны только игроку в игре; из консоли сервера они не выполняются.

### `/ps plot delete <название|id>`

Удаляет участок. Доступно владельцу участка, владельцу основной защищённой зоны и администратору с `protectionstones.admin`.

### `/ps plot add <название|id> <игрок>`

Даёт игроку доступ к участку.

### `/ps plot kick <название|id> <игрок>`

Лишает игрока доступа к участку. Блокировка действует **даже если игрок добавлен в основную защищённую зону (приват от блока)** — внутри участка он не сможет ломать и ставить блоки, работать вёдрами, открывать контейнеры, двери и калитки, нажимать кнопки и плиты, взаимодействовать с рамками, вредить блокам взрывом с определяемым игроком-источником и атаковать существ напрямую или снарядами.

Личные действия с предметом — еда, питьё, надевание элитр и зарядка оружия — не блокируются только из-за того, что прицел наведён на участок. Опасный результат такого действия внутри участка блокируется соответствующим игровым событием.

**Нюансы сообщений и снарядов:**
- Сообщение «нет доступа» приходит не чаще одного раза в две секунды, чтобы удержанная кнопка мыши не заливала чат
- Бесполезный правый щелчок по обычному блоку (земля, камень) молчит: он и так ничего не делает. Сообщение приходит, когда действие могло сработать — интерактивный блок либо блок, ведро, огниво или рамка в руке
- Заблокированный снаряд не уничтожается: он останавливается и падает, поэтому брошенный трезубец не теряется

### `/ps plot unkick <название|id> <игрок>`

Снимает блокировку, но **не возвращает доступ**. Игрок переходит в промежуточное состояние — «прохожий»: он больше не в чёрном списке, однако участок для него закрыт так же, как для любого постороннего человека с улицы.

Разница между двумя состояниями видна только при выставленных флагах:

| | Заблокирован (`kick`) | Прохожий (`unkick`) |
|---|---|---|
| Ломать и ставить блоки | ❌ | ❌ |
| Обычный участок без флагов | ничего нельзя | ничего нельзя |
| Участок с `interact allow` | ❌ по-прежнему нельзя | ✅ можно, наравне со всеми |
| Участок с `chest-access allow` | ❌ по-прежнему нельзя | ✅ можно, наравне со всеми |

**Зачем это нужно.** Игрок, добавленный в основную защищённую зону, автоматически получает полный доступ ко всем участкам внутри неё. Промежуточного состояния «он в зоне, но конкретный участок для него чужой» без этой команды не существует: либо полный доступ, либо чёрный список. `unkick` даёт третий вариант — закрыть от человека один сарайчик, не занося его в чёрный список и не мешая ему пользоваться общими фермами.

**Важное ограничение.** `unkick` — это не отмена `kick`. Команда `kick` удаляет игрока из участников участка, и восстановить эту запись нечем. Если до блокировки у игрока был личный доступ через `/ps plot add`, после `unkick` он не вернётся — выдайте доступ заново командой `/ps plot add`.

Три состояния и переходы между ними:

```
/ps plot add    → полный доступ
/ps plot unkick → прохожий: только публичные флаги
/ps plot kick   → чёрный список: не действует ничего
```

Команды взаимно перекрывают друг друга: игрок всегда находится ровно в одном состоянии. Владельца основной зоны нельзя перевести ни в одно из ограниченных состояний.

### `/ps plot kickall <игрок>`

То же самое, что `kick`, но сразу для всех участков текущего мира, которыми ты управляешь.

### `/ps plot list`

Показывает управляемые игроком участки в текущем мире: название, родительскую зону, координаты углов и явные UUID-доступы. Игроки, получившие доступ через основную зону (блок привата), помечаются как `(via parent)`. Состав внешних WorldGuard/permission-групп в список не разворачивается, но владелец через WG-группу может управлять участком и сохраняет доступ.

Если на участке есть ограниченные игроки, в строку добавляются ещё два поля:

- `Blocked:` — заблокированные через `/ps plot kick`, красным
- `Guests:` — переведённые в состояние «прохожий» через `/ps plot unkick`, жёлтым

### `/ps plot flag <название|id> [interact|chest-access] [allow|deny|none]`

Управляет флагами WorldGuard непосредственно на участке, независимо от флагов родительской зоны.

**Доступные флаги:**

| Флаг | Что разрешает |
|---|---|
| `interact` | Правый клик по блокам: кнопки, рычаги, двери, нажимные плиты, зачарователи, верстаки и т.д. |
| `chest-access` | Открытие контейнеров: сундуки, бочки, шалкеры |

**Значения:** `allow` — разрешить для всех, `deny` — явно запретить, `none` — сбросить (наследуется от родительской зоны).

Без явной установки флаги **всегда наследуются** от родительской зоны — поведение по умолчанию не меняется.

Без аргументов (`/ps plot flag <название>`) показывает флаги, выставленные непосредственно на участке.

**Пример — ферма опыта с общедоступным сундуком:**
```
/ps plot create storage      ← выделить зону вокруг сундука/зачарователя
/ps plot flag storage interact allow       ← все могут нажимать кнопки и т.п.
/ps plot flag storage chest-access allow   ← все могут открывать сундуки
# ломать блоки по-прежнему нельзя — наследуется запрет от основной зоны
```

Флаги не обходят список заблокированных игроков (`/ps plot kick`) — кикнутый игрок не получит доступ, даже если флаг выставлен в `allow`. Если нужно, чтобы человек всё же пользовался общей фермой, но не имел доступа к участку, переведите его в состояние «прохожий» командой `/ps plot unkick`.

## Права доступа к участку

Доступ вычисляется по формуле:

> **(участники основной зоны ∪ участники участка) − заблокированные**

| Ситуация | Доступ к участку | Доступ к остальной зоне |
|---|---|---|
| Добавлен в основную зону (`/ps add`) | ✅ | ✅ |
| Добавлен только в участок (`/ps plot add`) | ✅ | ❌ |
| Добавлен в оба | ✅ | ✅ |
| Заблокирован в участке (`/ps plot kick`) | ❌ — даже если в основной зоне, и публичные флаги не помогают | ✅ остальная территория |
| Переведён в «прохожие» (`/ps plot unkick`) | ❌ личного доступа нет, но публичные флаги участка действуют | ✅ остальная территория |
| Удалён из основной зоны (`/ps remove`) | ❌ — автоматически теряет и участки | ❌ |

**Владелец основной защищённой зоны всегда имеет полный доступ ко всем участкам внутри неё.** Команда `kick` на владельца не действует.

`protectionstones.admin` и WorldGuard bypass намеренно не отменяют явный `/ps plot kick`. Право `protectionstones.plot` имеет `default: op` и может быть выдано обычным игрокам через permission-плагин.

### Что происходит при удалении из основной зоны

Когда игрок удаляется из основной зоны командой `/ps remove` или `/ps removeowner`, он автоматически удаляется из всех участков этой зоны. В чате отображается количество затронутых участков. Одновременно снимаются и все ограничения на этих участках — и блокировка, и статус «прохожий», — чтобы при повторном добавлении в зону не осталось забытых пометок.

Если у игрока не было такой роли в зоне, команда сообщит об этом и ничего не изменит. В частности, игрок, добавленный **только** в участок через `/ps plot add`, не теряет этот доступ от `/ps remove` — его там и не было в основной зоне.

## Вложенные зоны защиты

Если внутри одной защищённой зоны находится другая, система автоматически привязывает новый участок к **наименьшей зоне, которая целиком вмещает выделение**:

```
Зона A (большая)
└── Зона B (средняя, внутри A)
    └── Зона C (маленькая, внутри B)

Выделение внутри C             → участок привязывается к C
Выделение внутри B, но вне C   → участок привязывается к B
Выделение внутри A, но вне B   → участок привязывается к A
Выделение пересекает две зоны  → ошибка, создание отклонено
```

При удалении зоны удаляются только напрямую привязанные к ней участки.

Merge, auto-merge, admin forcemerge и unmerge запрещены, пока у затрагиваемой зоны есть участки. Сначала удали или вручную перенеси участки, затем повтори операцию. Автоматический reparent при изменении геометрии намеренно не выполняется, чтобы не повредить данные.

---

## Автоматическая очистка

- **При удалении защищённой зоны** — все её участки удаляются вместе с ней.
- **При старте сервера** — удаляются участки с отсутствующим или подменённым parent, неверным WG-parent либо геометрией за пределами родительской PS-зоны. Причина логируется.

## Граница защиты

Защита `/ps plot kick` покрывает обычные игровые действия, которые Paper передаёт через Bukkit-события: блоки, взаимодействия, сущности, рамки, снаряды, вёдра, многоблочную установку и взрывы с определяемым игроком-источником. WorldEdit, административные команды и другие доверенные плагины могут напрямую менять мир или WorldGuard; защита от произвольного кода таких плагинов не является частью этой модели безопасности.

## Конфигурация

В `config.toml` сервера добавляется секция:

```toml
[plot]
    # Стоимость создания участка (требует Vault). 0.0 — бесплатно.
    create_cost = 50.0
```

На уже работающем сервере значение в существующем `plugins/ProtectionStones/config.toml` сохраняется. Чтобы применить новую цену, измените там `plot.create_cost` на `50.0` и перезагрузите конфигурацию или сервер.
